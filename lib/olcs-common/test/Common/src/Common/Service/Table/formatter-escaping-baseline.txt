# Values a type constraint keeps off the page rather than an escaping call: the formatter
# requires a number or a parseable date, and neither can contain "<script>".
#
# Each one is put back on its own — the payload restored at exactly that path, every other
# value left as the settled run had it, and the formatter called once more with no
# adaptation. Being listed here means that call threw and had written nothing by then, so
# the constraint rejects the value before it can reach the output. In production the same
# input is a 500, not a payload on a page.
#
# That is a proof rather than an exemption, and it is re-derived on every run, so it cannot
# outlive the constraint that justifies it. It is still narrower than "this value is
# escaped", which is why it stays recorded and is asserted in both directions.
#
# One path at a time, never in a batch, and the conversation formatters show why:
# getFirstReadBy() returns early when createdBy.id equals the read's user.id, so restoring
# the payload to both at once would skip the branch and report "no leak" about code that
# never ran. Isolated, both of those values render and come out escaped, so neither is
# listed — they are covered like any other value.
#
# Dotted paths come from a hand-written fixture (see RowFixtures) — the same accounting
# applies to those, so a fixture cannot quietly de-probe a value and still read as covered.
